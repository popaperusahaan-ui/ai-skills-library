# Versioning and Releases

This document explains how versions and releases are managed in AI Skills Library.

## 1. Purpose

Versioning helps users identify changes, improvements, and updates to the library.

## 2. Version Format

The repository follows Semantic Versioning:

MAJOR.MINOR.PATCH

- MAJOR: Significant changes that may affect compatibility.
- MINOR: New Skills or backward-compatible improvements.
- PATCH: Bug fixes and minor documentation updates.

## 3. Release Types

### Major Release

Introduces significant structural or compatibility changes.

### Minor Release

Introduces new Skills or substantial improvements.

### Patch Release

Fixes errors and improves existing documentation.

## 4. Changelog

Every notable update should be recorded in `CHANGELOG.md`.

Changelog entries should include:

- New Skills.
- Improved Skills.
- Bug fixes.
- Documentation changes.
- Breaking changes.

## 5. Release Preparation

Before publishing a release:

- [ ] Review repository changes.
- [ ] Validate all Skill files.
- [ ] Update CHANGELOG.md.
- [ ] Check documentation.
- [ ] Choose an appropriate version number.
- [ ] Create a GitHub release.

## 6. Release Tags

Use version tags such as:

- v1.0.0
- v1.1.0
- v1.1.1

## 7. Release Notes

Each release should explain:

- What changed.
- Which Skills were added.
- Which Skills were improved.
- Important fixes.
- Known limitations.

## 8. Maintenance

The repository owner is responsible for reviewing and maintaining releases.

## 9. Goal

Maintain a clear, traceable, and reliable update history for AI Skills Library.
