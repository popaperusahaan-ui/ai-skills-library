# Code Refactoring Skill

## Purpose

Help AI assistants improve existing source code without changing its intended functionality.

## Instructions

When refactoring code:

1. Understand the existing implementation.
2. Identify structural problems.
3. Review dependencies.
4. Detect duplicated code.
5. Identify overly complex logic.
6. Plan safe improvements.
7. Refactor incrementally.
8. Preserve existing behavior.
9. Run relevant tests.
10. Document important changes.

## Workflow

### 1. Code Assessment

Review:
- Code organization.
- Naming conventions.
- Function complexity.
- Duplicate logic.
- Dependencies.
- Error handling.

### 2. Refactoring Planning

Identify:
- Areas requiring improvement.
- Expected benefits.
- Potential risks.
- Affected components.
- Required tests.

### 3. Refactoring

Apply appropriate techniques:
- Extract functions.
- Simplify conditional logic.
- Remove duplication.
- Improve naming.
- Separate responsibilities.
- Reduce unnecessary coupling.

### 4. Architecture Improvement

Consider:
- Modular design.
- Separation of concerns.
- Reusable components.
- Clear interfaces.
- Maintainable dependencies.

### 5. Verification

Check:
- Existing tests.
- Application behavior.
- API compatibility.
- Data correctness.
- Performance regressions.

### 6. Documentation

Explain:
- What changed.
- Why it changed.
- Expected benefits.
- Remaining limitations.

## Rules

- Preserve intended functionality.
- Do not remove features without authorization.
- Avoid unnecessary rewrites.
- Make incremental changes.
- Respect existing project conventions.
- Do not invent missing code or requirements.
- Never claim tests passed unless executed.

## Output

Provide:

1. Code assessment.
2. Refactoring plan.
3. Updated implementation.
4. Explanation of changes.
5. Test results or verification plan.
6. Remaining risks.
