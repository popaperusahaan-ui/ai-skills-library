# Software Architecture Review Skill

## Purpose

Help AI assistants evaluate software architecture and recommend practical improvements.

## Instructions

When reviewing software architecture:

1. Understand business and technical requirements.
2. Examine the existing architecture.
3. Identify system components and dependencies.
4. Review data flows and integration points.
5. Evaluate scalability and reliability.
6. Assess security and privacy.
7. Identify architectural risks.
8. Compare possible improvements.
9. Recommend appropriate solutions.
10. Document findings and trade-offs.

## Workflow

### 1. Architecture Discovery

Identify:
- Application components.
- Services and modules.
- Data storage systems.
- External integrations.
- Deployment environments.
- Technology dependencies.

### 2. Design Evaluation

Review:
- Separation of concerns.
- Modularity.
- Component responsibilities.
- Coupling and cohesion.
- Data consistency.
- Interface design.

### 3. Quality Assessment

Evaluate:
- Scalability.
- Performance.
- Reliability.
- Maintainability.
- Security.
- Observability.
- Cost efficiency.

### 4. Risk Identification

Identify:
- Single points of failure.
- Unnecessary complexity.
- Tight coupling.
- Scalability limitations.
- Security weaknesses.
- Operational risks.

### 5. Improvement Planning

Recommend:
- Architectural improvements.
- Better component boundaries.
- Appropriate design patterns.
- Integration improvements.
- Reliability strategies.
- Migration approaches.

### 6. Documentation

Provide:
- Architecture diagrams when useful.
- Component descriptions.
- Data flow explanations.
- Design decisions.
- Risks and trade-offs.

## Rules

- Do not invent existing system components.
- Preserve important requirements.
- Avoid unnecessary architectural complexity.
- Explain trade-offs clearly.
- Consider implementation cost.
- Do not recommend migrations without explaining their risks.
- Never claim an architecture is production-ready without sufficient evidence.

## Output

Provide:

1. Architecture overview.
2. Design assessment.
3. Identified weaknesses.
4. Risk analysis.
5. Improvement recommendations.
6. Suggested architecture.
7. Migration considerations.
