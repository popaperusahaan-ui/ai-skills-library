# Application Security Skill

## Purpose

Help AI assistants build, assess, and maintain secure applications throughout the software development lifecycle.

## Instructions

When working on application security:

1. Understand application architecture.
2. Identify sensitive assets and data.
3. Review authentication and authorization.
4. Inspect input validation and output handling.
5. Assess dependency security.
6. Review session management.
7. Evaluate data protection.
8. Identify security weaknesses.
9. Recommend appropriate fixes.
10. Verify security improvements.

## Workflow

### 1. Security Requirements

Identify:
- Application components.
- User roles and permissions.
- Sensitive data.
- External integrations.
- Security requirements.
- Compliance considerations.

### 2. Architecture Review

Examine:
- Application boundaries.
- Data flows.
- Authentication mechanisms.
- Authorization rules.
- External services.
- Storage systems.

### 3. Code Security Review

Review:
- Input validation.
- Output encoding.
- Access control.
- Session handling.
- Error handling.
- Dependency management.
- Secret management.

### 4. Defensive Controls

Recommend:
- Secure authentication.
- Least-privilege permissions.
- Strong authorization checks.
- Encryption.
- Secure session management.
- Rate limiting.
- Security logging.

### 5. Security Testing

Use authorized, non-destructive tests to evaluate:
- Authentication behavior.
- Access permissions.
- Input validation.
- Data exposure.
- Security configurations.
- Error handling.

### 6. Remediation

Provide:
- Clear explanations.
- Risk prioritization.
- Secure code improvements.
- Configuration recommendations.
- Regression tests.

## Rules

- Protect credentials and sensitive information.
- Never expose private user data.
- Validate all untrusted input.
- Enforce authorization on the server side.
- Do not disable security controls to hide vulnerabilities.
- Only test systems with authorization.
- Preserve existing application functionality.
- Never claim fixes are verified without evidence.

## Output

Provide:

1. Application security assessment.
2. Identified vulnerabilities.
3. Risk prioritization.
4. Recommended fixes.
5. Secure implementation examples.
6. Verification checklist.
